# 7. CI / CD (GitHub Actions)

## `ci.yml` — every push and pull request

| Job | Steps |
|-----|-------|
| `tools` | `go vet ./...`, `go test ./...` in `tools/`; `ldm catalog` (validates every manifest) |
| `site` | `npm ci`, `npm test` (`node --test` on `tests/site/`, covering `site/assets/js/lib`), `npm run build:css` |
| `languages` | Reads `catalog/languages.json` and emits the language list as a job matrix |
| `verify` (matrix per language) | `bin/bench.sh -verify-only -lang <id>`: builds every image of that language and runs all verification cases |

The verify matrix is generated from the catalog, so adding a language needs no workflow edit.

## `bench.yml` — benchmarks + website deployment

Triggers: push to `main` touching `projects/`, `catalog/`, `bin/`, `tools/`, `site/` or the workflow;
weekly schedule (Monday 03:00 UTC); manual `workflow_dispatch`.

| Job | Steps |
|-----|-------|
| `bench` | `bin/bench.sh` (all projects × languages, **one runner, sequential**) → `bin/build.sh` (catalog + CSS) → upload `results.json` as an artifact → upload `site/` as the Pages artifact |
| `deploy` | `actions/deploy-pages` to the `github-pages` environment |

Concurrency group `pages` prevents two deployments from racing. Benchmarks run with
`-cpuset 1` to pin the measured process to one CPU.

## Setup required on GitHub

1. *Settings → Pages → Source*: **GitHub Actions**.
2. Nothing else: the workflows only use `GITHUB_TOKEN` with `pages: write` and `id-token: write`.
