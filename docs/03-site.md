# 3. Website

## Tech stack

| Concern | Choice | Notes |
|---------|--------|-------|
| DOM / events / AJAX | **jQuery 4.0.0** | No framework, no bundler |
| Styling | **Tailwind CSS 4** | Compiled once with `@tailwindcss/cli` into `site/assets/css/app.css` |
| Charts | **Apache ECharts 6.1** | Bar, box-plot and grouped charts; dark theme tuned to the site |
| Syntax highlighting | **highlight.js 11.11** | Plus `x86asm` and `dockerfile` language packs |
| Fonts | Inter (UI), JetBrains Mono (code), Teko (announcer / display) | Google Fonts |
| Routing | Hash routes (`#/projects/fibonacci/code/rust`, `#/deathmatch/algorithms/rust/go`) | Works on GitHub Pages without rewrites |
| Data | Static JSON generated by `ldm catalog` and `ldm bench` | `site/data/*.json` |

CDN scripts are pinned to exact versions with SRI hashes. The site is **dark-themed**
(a light theme is 🔜 planned).

## JavaScript structure

Native **ES modules**, no bundler: `index.html` loads jQuery, ECharts and highlight.js as
classic scripts (globals `$`, `echarts`, `hljs`) and then one entry module, `app.js`.

```
site/assets/js/
├── lib/        # pure logic, no DOM — unit tested with `node --test` (tests/site/)
│   ├── format.js     durations, bytes, numbers, ratios, HTML escaping, page titles
│   ├── stats.js      ranking per case/metric, relative factors, leaderboard (geometric mean)
│   ├── filters.js    project explorer filtering & sorting
│   ├── router.js     hash → route object, route → hash
│   ├── store.js      data store with an injected fetchJson (mockable), caching
│   ├── arena.js      deathmatch arenas: per-case medians, lines of code, open/locked
│   ├── fight.js      rules of combat: blows, damage, rounds, matches
│   ├── tournament.js round-robin standings, towers
│   ├── progress.js   tower climbs over injected storage
│   ├── fight-script.js match → animation steps + commentary
│   └── player.js     step playback with injected timers
├── ui/         # DOM helpers (jQuery)
│   ├── components.js badges, chips, cards, panels, empty states
│   ├── charts.js     ECharts wrappers (ranked bars, box plot), resize & disposal
│   ├── code.js       code viewer: file tabs, line numbers, copy button, highlight.js
│   ├── fighter.js    fighter emblems, portraits, arena titles, result badges
│   ├── fight-stage.js fight HUD, sprites, announcer; renders fight-script steps
│   └── storage.js    localStorage adapter with in-memory fallback
├── views/      # one module per page; render(ctx) writes HTML and binds events
│   ├── home-page.js, home.js, home-deathmatch.js  hero + roster, champions, explorer, arenas
│   ├── deathmatch.js + deathmatch-*.js  select, rankings, tower, fight (+ result/scorecard)
│   ├── project.js + project-*.js        header, tabs: overview, code, compare, benchmarks
│   ├── leaderboard.js, pages.js (fighters, 404), methodology.js
│   └── shared.js                        ranking charts/table, environment card, helpers
└── app.js      # bootstrap: data store, storage, hash router, view dispatch, nav & footer
```

Interactive controls (filters, benchmark case/metric/scale, leaderboard metric) update the URL
query with `history.replaceState`, so views are shareable without re-rendering the page.

## Charts and color

Languages always sit on a labelled category axis, so bars use **one validated series hue**
(`#3987e5` on the `#12151c` surface). Language brand colors fail categorical-palette checks
(Python and C++ are both blue; Rust and Assembly read as gray), so they only appear as small
identity dots next to text labels. Every chart has a hover tooltip, a table or text equivalent,
and a linear/log toggle where values span orders of magnitude (log base 2 for memory).

### Deathmatch layer

The fight screens add a fighting-game layer on the same dark palette: the **Teko** display font with
a gold-to-ember gradient for announcer text (`.dm-title`), `--color-gold` for round medallions and
champions, `--color-blood` for K.O. and fatality accents, and each arena's `color` as the stage glow.
Brand colors appear only on fighter glyphs (large display text). Animations are CSS keyframes whose
durations divide by the player's speed (`--speed`); `prefers-reduced-motion` disables them all.
Styles live in `site/assets/css/deathmatch.css`, imported into Tailwind's `components` layer.

## Pages and features

### Deathmatch — `#/deathmatch…` ✅

The arcade mode: choose a fighter and an arena, climb the tower, watch every fight as an animated
replay of the benchmark numbers, see the arena rankings. Rules, screens, routes and storage are
described in [Deathmatch](10-deathmatch.md).

### Home — `#/` ✅

- Hero: name, tagline, *Choose your fighter* / *Browse the code*, the fighter roster (each links to
  the select screen with that fighter), counters (fighters, open arenas, projects, last benchmark).
- **Reigning champions**: the rank-1 fighter of every open arena → its rankings.
- **Arenas**: every category with its stage name, project count, open/locked state, links to its
  projects (filters the explorer) and rankings.
- **Project explorer**:
  - Free-text search (name, summary, tags).
  - Category filter (select), complexity filter (level pills 1–5), language filter
    ("implemented in").
  - Sort: by level (default), by name.
  - Project cards: name, summary, category, level badge, tags, language coverage dots,
    and — when results exist — the fastest language for the project's first benchmark case.
  - Filters are reflected in the URL query (`#/?q=fib&level=1&cat=algorithms&lang=rust`),
    so filtered views can be shared.

### Project — `#/projects/:id[/:tab[/:a[/:b]]]` ✅

Header with name, summary, category, level, tags and language coverage. Tabs:

| Tab | Route | Content |
|-----|-------|---------|
| Overview | `#/projects/fibonacci` | Spec: description, input, output, rules; verification cases table; benchmark cases |
| Code | `…/code/:lang` | Language tabs (brand colored) → file tabs → highlighted code, copy button, toolchain, build command, LOC, implementation notes |
| Compare | `…/compare/:a/:b` | Two language pickers; code side by side (stacked on mobile); per-case metric comparison ("Rust is 41.3× faster than Python") |
| Benchmarks | `…/benchmarks` | Case selector; metric selector (wall time, CPU time, peak memory); ranked bar chart; box plot of wall-time samples; sortable results table; static metrics (LOC, image size) chart; verification status per language; environment card |

### Leaderboard — `#/leaderboard` ✅

Overall ranking across every benchmark case of every project: for each case a language's
score is `median / best median`; the overall score is the **geometric mean** of its scores,
with coverage (number of cases) and wins shown. Separate rankings for wall time, CPU time and peak memory.

### Fighters — `#/fighters` ✅

One card per language: emblem, name, nickname, kind, quote, special move, fatality, arena titles
(arenas where it ranks first), toolchain image, number of implementations, rank and score in the
wall-time leaderboard, and a link to fight as that language.

### Methodology — `#/methodology` ✅

How benchmarks are run (harness, warmups, runs, verification), metric definitions,
statistics, fairness rules, **fight rules** (`#/methodology?section=fight-rules`), and the
environment of the last run (CPU, cores, kernel, Docker version, commit, date).

### Not found ✅

Any unknown route or project id renders a friendly 404 with a link home.

## States

| State | Behavior |
|-------|----------|
| Loading | Skeleton blocks while JSON loads |
| No results yet (`results.json` missing) | Benchmarks tabs and the deathmatch show an explanation and the command to produce them; code browsing works |
| Arena locked / fighter without results there | The deathmatch explains why and links back to the select screen |
| Implementation failed verification | Shown with a red "failed" badge and the failure reason; excluded from rankings |
| Language without implementation | Greyed out ("not implemented yet") in coverage; absent from language pickers |

## Responsive & accessibility

- Mobile first; 16px gutters; side-by-side compare becomes stacked under `lg`.
- Charts resize with the window; tables scroll horizontally inside their own container.
- Keyboard-focusable tabs and buttons, visible focus rings, `aria-selected` on tabs,
  sufficient contrast on the dark palette.
